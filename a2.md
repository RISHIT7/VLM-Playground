#### 1.1 Contrastive Language-Image Pre-training (CLIP)

You will implement a weakly-supervised model inspired by CLIP. You will use the programmatically generated captions provided in the datasets to align image and text modalities. We only provide some basic hyper-parameter details, however you should read the paper carefully to understand other detailed nuances.

---

As shown in 1, the model consists of an image encoder, a text encoder, and a shared embedding space in which aligned image text pairs are brought close together using a contrastive objective.

**Overall model:** Given an image I and its caption T, the model produces an image embedding $v\in\mathbb{R}^{d}$ and a text embedding $t\in\mathbb{R}^{d}$. Both embeddings are l2-normalized and compared using temperature-scaled cosine similarity. The temperature is a learnable parameter and is initialized to $\log(1/0.07)$ following the details described in the CLIP paper [5]

**Vision Transformer image encoder:** The visual pipeline should follows the standard ViT design [2]. The image encoder is a Vision Transformer consisting of 12 transformer layers, 6 attention heads per layer, hidden dimension 384 and MLP dimension 1536. In the experiments use the patch size of 16 and the input image resolution is fixed at $224\times224$. You must project your final output into a 512 dimensional shared space. Each transformer layer can be implemented via Pytorch abstractions like nn.MultiheadAttention, nn. Linear etc. Use of fully abstracted Transformer and Transformer Layer is not allowed.

**Text encoder:** The text branch is a lightweight transformer. It should be implemented with 6 transformer layers, 6 attention heads, 384 hidden dimension and 1536 MLP dimension. Refer to [6] for details. After the transformer stack, the representation of the final non-padding token (effectively the end-of-text token) should be projected into the joint embedding space(512 dimensional).

**Tokenizer and Caption representation:** Instead of using a pretrained tokenizer, You should construct a simple task-specific tokenizer directly from the training captions. You can choose a fixed context length for training the model. Each caption is formed directly from the scene graph and encodes object count and attributes such as size, color, material, and shape. A typical caption has the form:

> An image with 3 objects: 1 small red metal cube, 2 large blue rubber spheres
> Since, no spatial information is used in the captions, therefore many different images can share the same caption. If several identical captions appear in one contrastive batch, the learning signal becomes less clean. You must take this into account while constructing your batches.

**Objective Function and Optimization:** Training uses the standard symmetric CLIP objective described in the paper. You can follow these parameters as default, however feel free to experiment on the best setting that works for you (You can refer to the paper for additional values of hyper-params): Optimizer=AdamW, learning rate = $5\times10^{-4}$ weight decay = 0.2, $\beta_{1}=0.9$, $\beta_{2}=0.98$, $\epsilon=10^{-6}$, epochs: 100, LR Scheduler: Cosine Decay with Linear warmup.

#### 1.2 Self-Supervised Distillation - DINO

You will implement a self-supervised model inspired by DINO. Unlike CLIP, this model does not use text at all. It learns visual representations by enforcing consistency between different augmented views of the same image. Similar to CLIP, we only provide basic hyper-parameter details, you should carefully read the [1] for detailed instructions.

**Overall framework:** The model consists of two networks with identical architecture:

- a student network, which is updated by gradient descent,
- a teacher network, not updated by backpropagation; instead, its parameters are updated as an exponential moving average of the student parameters.

Both the Teacher and Student models must use the same Vision Transformer backbone as used in CLIP (12 layers, 6 heads and 384 hidden dimension). On top of the ViT backbone, both models use a projection head of 4096 dimension which maps the backbone feature into the space used for self-distillation. (Note that this is different from the paper which uses a 65536 dimensional feature space). Feel free to figure out what works best here as well.

---

**Multi-crop data augmentation:** A central component of DINO is the augmentation pipeline. For each image, the transform produces: (1) two global crops of size $224\times224.$ (2) several local crops of size $96\times96$ You can use the default number of local crops as 8, so each image yields 10 views in total. Refer to the paper for more details on the different augmentation strategies applicable.

**Teacher-student training rule:** During training, the student receives all augmented views and the teacher receives only the two global views. The teacher is not updated by backpropagation. Instead, its parameters are updated as an exponential moving average of the student parameters as specified in the paper. The objective function is cross-entropy between the teacher probability distribution for one global crop and the student prediction for every other crop of the same image, excluding the matching same-view pair. The final loss averages this over all valid teacher-student crop pairs. Refer to Equation 3 in [1].

**Centering mechanism:** A key stabilization component is the running center which is an exponential moving average of the teacher outputs across batches. Before applying softmax to the teacher outputs, the current center is subtracted. Refer to Equation 4 and Algorithm 1 in [1]. This prevents the teacher distribution from becoming too peaky and helps avoid representation collapse.

**Optimization:** Training is performed only on the student network. The optimizer to be used is AdamW with same default hyper-parameters as CLIP. You're free to ablate your hyper-parameter choices.
